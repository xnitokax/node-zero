# NODE//ZERO

ターミナルにコマンドを打ち込み、サーバーからサーバーへ「転移」しながら事件の真相を探る、ハッキング風の推理ゲームです。
マーダーミステリー用のシナリオの仕組みを試すための、一人用の試作版です。

## 遊び方

深夜、ネクサス社の研究主任がサーバー室で「感電事故」で死亡した。
依頼を受けたハッカーのあなたは、社内ネットワークに侵入して真相を探る。

- **ターミナル操作**：使うのは `ssh <名前>`（転移）と `back`（戻る）だけ。Tab で補完、↑↓ で履歴。接続先の名前をタップするとコマンドが入るので、スマホでも遊べる
- **トレース（逆探知）**：罠を踏んだりパスワードを間違えたりすると上がる。100%で接続が遮断される
- **鍵付きサーバー**：パスワードは別の場所の情報から推理する
- **一方通行**：踏むと戻れない
- **アクセスログ**：自分がいつどこへ移動したかが記録される
- **最後のコマンド**：報告画面で `expose <犯人>` を打つと、集めた証拠を送りつけるフィナーレ演出が始まる。どの証拠を見つけたかで結末が変わる（隠しエンディングあり）

## 工夫した点

### シナリオとエンジンの分離
シナリオはすべて `src/scenario.js` にデータとして書く形にしました。本文の中に `<a data-go="ノードID">` と書けば、それがそのまま接続先になります。
ターミナル側では、エンジンがリンクを読み取って `ls` の一覧と `ssh` の接続先に変換するので、シナリオを書く人はコマンドのことを意識しなくて済みます。
罠（`trap`）、鍵（`lock`）、一方通行（`data-oneway`）も属性を付けるだけで使えるので、エンジンのコードを触らずにシナリオを増やせます。
結末は「どのノードを訪れたか」（`requires`）を条件に上から順に判定するので、証拠の集め方によって結末を分けられます。
ビルド時には、存在しない転移先へのリンクや、結末の条件の書き間違いもチェックします。

### 鍵付きノードの暗号化
ブラウザで動く謎解きゲームは、答えのデータがプレイヤーの手元に届いてしまいます。そのため、パスワードを平文で持たせると、開発者ツールで簡単に突破できてしまいます。

そこでビルドのときに、鍵付きノードの本文を**そのノードのパスワードで暗号化**しています（PBKDF2 で鍵を作り、AES-GCM で暗号化）。
パスワードが正しいかどうかは、「復号に成功したか」（AES-GCM の改ざん検知）だけで判定しています。そのため、公開データの中には正解のパスワードも、そのハッシュ値も入っておらず、正しいパスワードを入れない限り本文は読めません。

**限界**：鍵のかかっていない部分（犯人やエンディングの文章など）はそのまま公開データに入っているので、読もうと思えば読めます。
完全に隠すには、答え合わせをサーバー側で行う必要があります。これは将来マルチプレイに対応するときに一緒に取り組む予定です。

## ファイル構成

```
src/scenario.js        シナリオ本体（⚠️ ネタバレ注意。パスワードが平文で入っています）
docs/                  公開されるファイル（GitHub Pages の公開元）
  index.html           ゲームエンジンと画面
  nz-crypto.js         鍵付きノードの暗号化・復号（ビルドツールと共用）
  scenario.data.js     ビルドで生成したシナリオデータ（自動生成）
tools/
  serve.ps1            開発用ローカルサーバー
  build.html           ビルドツール
```

## 開発

外部ライブラリも、Node.js などのランタイムも使っていません。Windows 標準の PowerShell とブラウザだけで開発できます。

```bash
powershell -ExecutionPolicy Bypass -File tools/serve.ps1
```

- ゲーム：http://localhost:8765/docs/
- ビルドせずに `src/scenario.js` を直接読み込んで確認する：http://localhost:8765/docs/?dev
- ビルド：http://localhost:8765/tools/build.html を開いて「ビルド」を押す → `docs/scenario.data.js` が更新される（存在しない転移先へのリンクもチェックします）
